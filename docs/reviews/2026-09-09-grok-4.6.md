## P1

**1. Correction-rate heuristic is not a correction rate.** `CORRECTION_RE` matches `always`, `never`, `stop`, `again`, `instead`, `actually`, `don't`, `do not`, `wrong`. Standing instructions fire it (`always use pnpm`, `stop only at a real blocker`, `don't forget the tests`). A5 fires for *any* rate once `user_turns >= 50` (`advise.py` 38–42) — 1% and 20% both become a “Correction rate” finding. Grok’s injected `/grok` boundary contains `Do NOT`; that string matches. Clustered “rules” from this regex are policy echo, not user pushback.

**2. Cache-read ratio and “API-equivalent cost” are not spend.** A4 is `cache_read_input_tokens / output_tokens > 150` (`monitor.py` 57). Claude Code re-reads a cached system+tool prefix every turn; 150× is harness-normal, not “you left a 40h session open.” Advice (“shorter sessions, subagents for reading”) does not shrink that prefix. Cost (`pricing.py`) is unverified third-party list prices (`verified=False`), including cache-read which dominates the dollar figure. Grok `usage` is left empty, so Grok never enters the cost loop: not in `cost_models_unknown`, contribution $0. `grok-4.5`/`grok-4.6` are both tiered `volume`, so A2 (orchestrator share) cannot fire on Grok even if you only ran the frontier model. Subscription users are shown a number nobody billed.

**3. Portable report leaks user text.** README and `adoption-review.md` promise “aggregates only (no text, no paths, no names).” The miner writes `repeated_corrections[].shape` = first 50 chars of the matching turn (`prompts/adoption-review.md` 76, 100) and `print()`s the JSON including that field. Short corrections are exactly where names, ticket keys, file names, and “revert the stripe key for X” live. Default `teyla monitor` also quotes a correction in A9 evidence (`advise.py` 64) even without `--samples`. Skill/plugin/MCP *names* go in `setup.md` and `skills`; the README’s “no names” is false.

**4. POLICY.md xAI ladder is wrong as of 2026-09-09.** `~/.grok/models_cache.json` (fetched 2026-09-09) lists **only** `grok-4.6` and `grok-4.5`. There is no “Grok 4.5 fast” or “Grok 4.5 mini”. `grok-4.6` is the current frontier (this runtime). Effort (`low|medium|high|xhigh` on 4.6) is not a SKU ladder. `pricing.py` itself says “single public tier.” Correct row:

| provider | orchestrate | volume | triage |
| xAI | Grok 4.6 | Grok 4.5 | none in CLI — do not invent mini/fast; use a cheaper provider or a smaller agent type (`explore`), not a fake SKU |

**5. Grok adapter drops real Grok usage.** `if len(s.user_turns) <= 1: s.sidechain = True` (`grok.py` 133–134) + CLI default `no_sidechain` (`cli.py` 32–33) hides one-prompt sessions. On the reviewed machine: **all** session dirs have 0–1 `prompt_history` rows; **0** have two. `teyla doctor` counts them; `teyla monitor` reports none. That is the actual Grok CLI pattern (`grok -p`, `/grok` from Claude). Layout otherwise matches (`~/.grok/sessions/<urlencoded-cwd>/<uuid>/`, `summary.json`, `signals.json`, `chat_history.jsonl` `tool_calls[].name`, cwd-level `prompt_history.jsonl`). Failures on top of the sidechain rule: `s.last` overwritten with last prompt ts (duration → 0); `compactionCount` unread; `spawn_subagent` unread; `modelsUsed` unique-list counted as 1; `_dir_size` is non-recursive; `GROK_HOME` ignored; hashed cwd + `.cwd` (documented, >255 bytes) unread.
