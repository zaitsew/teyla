## Research

Two second opinions on one brief, 2026-11-08: Grok 4.7 (high effort, $0.62) and Codex
GPT-6 Astra (high effort, web search). Both agreed on the decisions below without seeing each
other. Where they split: Grok said the owner is the user and analytics cannot steer yet;
Codex said owner preference cannot replace users completing tasks. We take both: the owner
decides direction and taste, testers check findability.

## Decisions

- **S12. Studio stays in Teyla; the taste corpus has an open format.** A separate product is
  reconsidered only after the system works on two products.
- **S13. Taste is evidence, not links.** An entry holds the URL, the owner's sentence verbatim,
  a verdict (like, dislike, mixed), a scope, axes, captured evidence (phone and desktop
  screenshots, computed styles, copy lines) and what not to copy. A link with no sentence stays
  `raw` and is never a style source. A model proposes the interpretation; only the owner
  makes an entry active.
- **S14. No averaging.** One direction per product: one primary reference, two supporting
  references, explicit exclusions. A dislike constrains only its named axis and wins over a
  like on it. A later entry supersedes an earlier one only in the same scope. Two products
  look alike only when the owner marks them as a family.
- **S15. DTCG tokens are the source; DESIGN.md is an export.** Google's DESIGN.md format
  (alpha, April 2026) is the delivery format for agents, not the database.
- **S16. Structure before screens.** Each product keeps an object model (objects, one home
  each, relations) and three jobs as sentences. A feature with no object, deeper than level 3,
  in "More", or a second home for an existing job triggers a structure review of that area.
- **S17. Two concepts, never a gallery.** Two structures on the same tasks and data; a third
  only when both fail. No token change while a structure change is open. The owner judges in a
  weekly batch of at most ten pairs.
- **S18. Every screen has a layout contract per size class** (compact, regular, wide), and a
  test enforces it. A wide window is never a cropped phone.
- **S19. The screen atlas is rendered from code.** A screen registry with stable ids and
  expected coverage; captures from UI-test tours, previews and snapshot tests; the atlas shows
  "captured / expected". The feature map is a graph built from the registry and the feature
  list. Figma gets atlas frames automatically, never hand-drawn screens (standard R20).

## Sprint 1 (the planner)

1. Week layout contract: a test that fails when a wide window draws fewer than seven days.
2. `teyla taste add`: the corpus, capture, and the chat channel.
3. Screen registry format, `teyla ux atlas` and the interactive feature map.
4. The planner: the registry for the first two navigation levels on iPhone and Mac, the full tour.
5. The planner: the object model and two structure concepts for "find an activity → put it in a day
   → see it on the map", for the owner to judge.

Success: the atlas shows more than 80 % of the expected first- and second-level screens; a
contract test has rejected a real regression; the owner picked a structure; four of five
testers finish the journey unassisted.
